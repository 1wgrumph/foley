## Changes

- `ui/replay.html` defines native landmarks, the recording comparison, evidence and navigation. `ui/replay.css` provides responsive layout, semantic colors, focus, theme and motion rules.
- `ui/player.js` aligns the two clocks using recorded actions and targets. It presents evidence as text, updates live data, and caches received media for offline playback.
- `ui/build.mjs` builds `ui/dist/replay.html` with inline CSS and a hashed script. `package.json` exposes the build. The ignored distribution file is regenerated by that command.
- `ui/render.mjs` validates the run with `src/run-schema.mjs`, confines artifact reads, selects evidence, inlines media and replaces the output atomically. `src/live.mjs` reuses its snapshot and confinement code for the read-only server.

## Design rationale

1. Equal-width recording and reproduction frames make the reported behavior and the browser result directly comparable.
2. The incident-console list fits action selection. Native step controls link the selected action to the source time.
3. A single row puts code location, measured runner exits and spend beside the playback controls.
4. Serif issue titles and monospaced timestamps distinguish the report from machine evidence. Text accompanies every status color.
5. On a phone the media stack in reading order. Live and recorded modes name themselves, and disconnect preserves the last complete view.

## Limits and handoff

The base run schema guarantees total cost. Per-step cost and token counts require attribution on a step or matching action. The UI labels absent measurements as unreported. It takes a per-run cap when provided and otherwise labels the documented $9 project ceiling. Runner exits come from an in-folder proof record; the census needs an in-folder census record to show more than the current issue. The page never infers runner exits or distributes a run total among steps.

The evidence uses synthetic inputs and controlled publications. The full CLI's offline pipeline case TC-R14-2 belongs to S4i. Real model usage, real-issue proof and judging remain outside this slice. BRAN discovery was unavailable because the worktree has no native BRAN policy. Source, fixtures and the interface note supplied the repository evidence.
