# W2 repair test interface

- Preserve the existing API, closed statuses, file locations and event fields. Offline authentication reads only `FOLEY_TEST_API_KEY`; live authentication reads only `MODEL_API_KEY`. The offline URL must have a literal loopback host (no `localhost` or DNS lookup). Tests intercept all fetches, independently check the product's redirect policy, and never connect to the live service.
- Wire body: `{model, messages, max_completion_tokens}` (existing chat wire field; provider enforcement still unverified). Freeze one normalized body before yielding. Price all UTF-8 bytes of its serialized JSON, including framing, at the uncached input price; for bounded image frames, replace the URL value with an empty string for byte counting and add 1,600 tokens per frame. No unbounded/remote image URL. For offline fixtures, bounded PNG images at most 1280 pixels on either axis qualify. Live protocol proof remains separate.
- `request_digest` is SHA-256 of the exact UTF-8 wire body, identical on retry; the corresponding prompt file retains text and only the decoded media digest. A known actual cost above the reservation is recorded in full, with request event `bound_violated: true`; persist a stop across later calls, even when global headroom remains. Later calls return `budget_refused` without transmitting.
- Refuse or redact the configured synthetic credential wherever it appears in successful output, usage, prompt or case metadata. Invalid nonnumeric usage yields `malformed_output` and unknown cost stays booked. JSON reply content must be a non-null, non-array object and arrive as a string.
- Maintain `cases` as own nonnegative safe-integer counters; inherited names are ordinary case IDs. Invalid case or reservation fields are `ledger_unreadable` before send.
- Persist sufficient event metadata to replay a lost trace projection: one original `baseline`, one `request` per transmitted call (including model, digest, outcome, tokens and cost/booked amount), one `refusal` per ordinary refusal; `recovery` for remaining booked liabilities. After restart, no duplication, last running total matches the ledger, and refusal events carry no request digest. Ordinary refusal leaves accounting unchanged. Extra journal fields/files are permitted.
- On blocked/broken storage or lock, `callEmber` returns `ledger_unreadable` rather than throwing or reporting success; preserve any booked/settled liability. A stale lock stays fail-closed until an operator quarantines it. Tests use only locks they own and explicitly remove the dead lock after checking refusal. Once storage is restored, the next locked call reconciles pending events. `recordBaseline` may throw a typed-safe error on storage failure, but must not lose a committed baseline event.
- Tests control external I/O boundaries (trace append/replace, ledger rename, lock release, HTTP response barrier) and the retry clock; no test-only hooks in product code required. Tests do not prescribe journal internals.

Persisted legacy open records (call ID, case ID, upper bound, optional PID) remain booked. PID liveness alone does not establish ownership; trace an unowned legacy reservation as recovery even if its PID has been reused.
